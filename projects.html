Selected Work

R-Type

Authoritative C++20 multiplayer remake of the 1987 arcade classic, built with a custom ECS and a UDP-first binary protocol.

Stack: C++20, SFML, ECS, UDP, CMake

About the project

R-Type splits gameplay from presentation: a headless server runs the real, authoritative simulation while a thin SFML client only renders and captures input. The two talk over a custom binary UDP protocol with explicit headers and bounds-checked serialization, and all gameplay logic runs on a lightweight custom ECS (rtype_engine) shared by both binaries, so the simulation stays deterministic and in sync across every connected player.

What I built

Built the SFML client renderer and contributed to server-side game systems and the network protocol.

AREA

Action-Reaction automation platform (IFTTT-style) connecting GitHub, Microsoft 365, Steam, and more through OAuth-driven workflows.

Stack: FastAPI, Vue 3, PostgreSQL, Docker, Android

About the project

AREA lets a user connect third-party services through OAuth, then chain an Action on one service to a Reaction on another — the same idea as IFTTT or Zapier. A FastAPI backend owns users, OAuth credentials, webhooks, and background schedulers; a Vue 3 web app and an Android companion app give two ways to build and monitor automations, with the whole stack running behind Docker Compose and a PostgreSQL database.

What I built

Built frontend views (services catalog, dashboard) and authored the architecture documentation.

Zappy

Multiplayer network game where teams compete on a resource-tile map — server, AI client, and 2D GUI over a custom protocol.

Stack: C, C++, Doxygen

About the project

Zappy is a real-time strategy game where several AI-controlled teams compete on a shared tile map, gathering resources and performing elevation rituals to win. The project is split into three pieces that only ever agree on a text protocol: a C server that owns the authoritative game state, an AI client written in any language, and a 2D GUI that visualizes the match live.

What I built

Built server networking (sockets, client lifecycle) and core game logic — resource distribution, player/egg management, time management.

Arcade

Game engine with dynamically loaded graphics and game modules — swap SDL2, SFML, or ncurses, and Snake, Nibbler, or Solar Fox, at runtime.

Stack: C++, dlopen, SDL2, SFML, ncurses

About the project

Arcade is built around runtime plugin-loading in C++: the core loads graphics libraries (SDL2, SFML, ncurses) and games (Snake, Nibbler, Solar Fox) as shared libraries via dlopen, so either one can be swapped live without recompiling. A shared IGraphics/IGame interface keeps every graphics backend and every game fully decoupled from the core — the main architectural challenge of the project.

What I built

Implemented the Nibbler game module and the graphics abstraction interfaces (IGame/IGraphics) shared across libraries.
